# Agent Control Tower

AI agents that share one notebook (a Meko Datapack) break in quiet ways. One reads an old fact, another skips a review step, a third reads memory it shouldn't. The control tower **runs real Claude Code and Codex agents**, captures what they do (prompts, streamed answers, tool calls, commands, file changes, errors), and joins that with what they read and wrote in the shared notebook. It then shows where the run drifted from the intended design, explains each issue from the evidence and proposes one fix. A person approves, and the change is applied and written back to the notebook as an audit trail.

```
POST /v1/agents/{id}/invoke ─▶ router (design.runtimes) ─▶ Claude Agent SDK │ Codex App Server
                                                               │ every visible event
                                                               ▼
                                     agent_invocations + agent_execution_events (PostgreSQL) ─▶ SSE
agents (SDK) ──read/write──▶ shared notebook (Meko, or local stand-in)
     │ tagged events (+ invocation_id)
     ▼
POST /v1/events ─▶ PostgreSQL ─▶ pipeline: 4 detectors → Summarizer (local Ollama) → Fixer (Claude)
                                   │ SSE
                                   ▼
                     control tower UI: design vs reality · issues · approve/reject
                                   │ approve
                                   ▼
             agent config / design changed + approval written to the notebook
```

**BlastX** is one small tool inside: pick any write and see every agent that read that version, plus everything they wrote because of it (`GET /v1/blast-radius`).

## Layout

| Path | What |
|---|---|
| `backend/` | FastAPI: ingest, detectors, Summarizer, Fixer, approvals, SSE (`app/`), schema (`migrations/`), tests |
| `backend/app/runtime/` | agent runtimes: `base.AgentRuntime`, `router`, `claude_sdk`, `codex_app_server`, `replay`, redaction, workspace checks |
| `docs/RUNTIME.md` | **runtime guide**: architecture, what is captured, API with real examples, curl commands, troubleshooting |
| `schemas/codex/` | Codex app-server protocol schema generated by the installed CLI (`codex app-server generate-json-schema`) |
| `workspaces/` | directories agents may work in (`demo-workspace` has the pricing sheet and a sample `auth.py`) |
| `scripts/live_smoke.py` | one real invocation through the backend, printing everything captured |

| `demo-agents/` | 4-agent content team; `config/*.yaml` is what fixes edit (and the runtimes' system prompts), `config.defaults/` restores the 3 planted bugs; `runtime_demo.py` runs the Codex + Claude demo (live or replay) |
| `scenarios/` | 18 planted-bug cases + runner that prints the catch rate |
| `design/design.json` | intended design: agents, handoffs, must-pass-through, memory permissions |
| `frontend/` | control tower UI (Vite + React + React Flow + Tailwind) |

## Run it locally (no paid services needed)

```bash
docker run -d --name tower-pg -e POSTGRES_PASSWORD=tower -e POSTGRES_DB=tower -p 5433:5432 postgres:16-alpine
python -m venv .venv && .venv/Scripts/pip install -r backend/requirements.txt -e sdk-python
cp backend/.env.example backend/.env
.venv/Scripts/python -m uvicorn app.main:app --app-dir backend --port 8000
cd frontend && npm install && npm run dev        # http://localhost:5174
python demo-agents/team.py                      # buggy run -> 3 issues appear live
# approve the 3 fixes in the UI, then:
python demo-agents/team.py                      # clean run; old issues flip to "resolved"
python -m scenarios.run --all --report          # caught 18 of 18 planted bugs, 0 false alarms
python demo-agents/team.py --reset              # put the planted bugs back for the next demo
```

Real agents (Codex researcher + Claude writer, full detect → fix → approve → verify loop):

```bash
.venv/Scripts/pip install claude-agent-sdk==0.2.176   # bundles the Claude Code CLI
.venv/Scripts/python -m tower.cli design push design/design.json
curl -s http://localhost:8000/v1/agents/providers/health
python demo-agents/runtime_demo.py --mode live --approve
```

See [docs/RUNTIME.md](docs/RUNTIME.md) for logins, models, curl commands and troubleshooting.

The database is plain PostgreSQL. The local notebook table stands in for Meko until we have access. `GET /v1/health` and the UI header say which parts are real.

**Summarizer = local Ollama** (`OLLAMA_MODEL`, default `qwen2.5:3b`). It's free, and run data never leaves the machine. Agents record why they did each thing (`tower.remember(key, value, why=...)`), and the model writes, per agent, what it did and why. Rows are grouped per agent so a small model keeps them apart. The digest's "notable" list is copied from the detectors, never written by the model. Install with `ollama pull qwen2.5:3b`. A run takes about 50s on CPU; issues show up immediately and the digest follows. A 7B/8B model is more accurate if you have the RAM. With `OLLAMA_MODEL` empty, or Ollama down, you get a counted digest instead.

Without `ANTHROPIC_API_KEY`, the Fixer uses rule templates. Set `MEKO_MCP_URL` and `ANTHROPIC_API_KEY` to switch to the real services. Run `list_meko_tools()` first and put the real tool names in `MEKO_TOOL_WRITE` / `MEKO_TOOL_SEARCH`.

## Tests

```bash
cd backend && ../.venv/Scripts/python -m pytest -q
```

There are 73 tests (+1 symlink test skipped where the OS user can't create symlinks):
- detector must-fire / must-stay-silent cases;
- 20 concurrent writes giving versions 1–20;
- ingest idempotency;
- the full ingest → fix → approve → verify loop;
- the Ollama summarizer with a mocked server, including its fallbacks, and guards against invented problems;
- the router: provider selection, disabled/unknown agents, workspace escapes, bad models, unsafe permission modes;
- the Claude adapter, fed the SDK's own message classes: capture, errors, cancel, permission checks;
- the Codex adapter against a fake app-server that speaks the real stdio JSON-RPC protocol: handshake, turn, approvals, failure, cancel/cleanup, malformed lines, resume, health;
- the invocation API, gap-free sequences, dedupe, replay after reconnect, SSE fan-out and filters;
- a mock end-to-end run with Codex + Claude invocations, a stale read, digest, fix, approval and verified rerun.

Live checks (they use your logins and quota): `python scripts/live_smoke.py researcher` and `python scripts/live_smoke.py writer`.

Database tests use a throwaway `tower_test` database and are skipped if no server is reachable.

## Where the guide is extended

- **`events.reason`:** the agent's own one-line "why", passed as `why=` in the SDK.
- **Summarizer:** local Ollama instead of Gemini, and the database is PostgreSQL instead of YugabyteDB (team decision).
- **`runs.scenario`:** reruns of the same scenario close the loop, so an approved issue becomes `resolved` or reopens.
- **`issues.detail` and `issues.note`:** the card's one-line explanation and the verification note.
- **`notebook_items` + `/v1/notebook`:** the Meko stand-in.
- **`GET /v1/health` and `POST /v1/runs/{id}/analyse`.**
- **SDK `recall(key, version=n)`:** reads one exact version. The demo writer uses it to reproduce reading from its own stale notes.
